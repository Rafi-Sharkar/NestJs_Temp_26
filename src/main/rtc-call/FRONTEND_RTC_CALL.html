Frontend Integration Guide: WebRTC RTC Call

This document provides a simple, direct guide for app and frontend developers to integrate the WebRTC voice and video calling features.

Namespace: /rtc-call (Connect via this path)
Authentication: Valid JWT Bearer token required in the connection handshake.

1. Connection Example

Pass the token via the auth object (common in Socket.IO).

import { io } from 'socket.io-client';

const rtcSocket = io('http://your-api-url/rtc-call', {
  auth: {
    token: 'Bearer YOUR_JWT_TOKEN',
  },
});

rtcSocket.on('connect', () => {
  console.log('Connected to RTC Gateway!', rtcSocket.id);
});

rtcSocket.on('connect_error', (err) => {
  console.error('RTC Connection failed:', err.message);
});

3. WebSocket Events Overview

Here is the quick reference for all events you can send (Emit) and receive (Listen).

Client Emit Event Server Response / Listener Input Payload (Type) Description
call:initiate call:incoming (to callee)
call:outgoing (to sender)		 { conversationId: UUID, type: "VOICE" | "VIDEO", offer?: string } Initiates a call. Emits the SDP offer to the callee.
call:ringing call:ringing (to caller) { callId: UUID } Callee client notifies the server they are ringing. Relays event to caller.
call:accept call:accepted (to caller) { callId: UUID, answer: string } Callee accepts call, returning their SDP answer. Sets call status to ACTIVE.
call:decline call:declined (to caller) { callId: UUID } Callee rejects/declines the incoming call request. Sets call status to DECLINED.
call:end call:ended (to all) { callId: UUID } Ends the active call session. Calculates total duration.
webrtc:offer webrtc:offer (to target) { callId: UUID, offer: string, targetUserId: UUID } Relays peer-to-peer WebRTC SDP offer directly.
webrtc:answer webrtc:answer (to target) { callId: UUID, answer: string, targetUserId: UUID } Relays peer-to-peer WebRTC SDP answer directly.
webrtc:ice-candidate webrtc:ice-candidate (to target) { callId: UUID, candidate: string, targetUserId: UUID } Relays and persists WebRTC ICE connection candidate.
call:toggle-audio call:participant-audio-toggled (to others) { callId: UUID, enabled: boolean } Notifies others if you muted/unmuted your microphone.
call:toggle-video call:participant-video-toggled (to others) { callId: UUID, enabled: boolean } Notifies others if you turned your video on/off.
call:toggle-screenshare call:participant-screenshare-toggled (to others) { callId: UUID, enabled: boolean } Notifies others if you toggled screensharing.

5. Example WebRTC Calling Flow

Below is the standard flow of operations and WebRTC signaling exchange between the Caller (Alice), the NestJS Server, and the Callee (Bob):

5.1 Sequence Diagram

sequenceDiagram autonumber actor Caller as Alice (Caller) participant Server as NestJS Server (/rtc-call) actor Callee as Bob (Callee) Note over Caller, Callee: Phase 1: Call Initiation & Setup Caller->>Server: Emit "call:initiate" { conversationId, type, offer } activate Server Server-->>Caller: Emit "call:outgoing" (Returns { success: true, call, ringingTo }) Server->>Callee: Emit "call:incoming" { callId, conversationId, initiatorId, type, offer, initiator } deactivate Server Callee->>Server: Emit "call:ringing" { callId } Server->>Caller: Emit "call:ringing" { callId, calleeId } Note over Caller, Callee: Phase 2: Call Acceptance / Decline alt Option A: Bob Accepts Callee->>Server: Emit "call:accept" { callId, answer } Server->>Caller: Emit "call:accepted" { callId, answer, calleeId } Note over Caller, Callee: Phase 3: ICE Candidate Exchange (Bidirectional) Caller->>Server: Emit "webrtc:ice-candidate" { callId, candidate, targetUserId } Server->>Callee: Emit "webrtc:ice-candidate" { callId, candidate, senderId } Callee->>Server: Emit "webrtc:ice-candidate" { callId, candidate, targetUserId } Server->>Caller: Emit "webrtc:ice-candidate" { callId, candidate, senderId } Note over Caller, Callee: Phase 4: In-Call Controls (e.g., Mute) Callee->>Server: Emit "call:toggle-audio" { callId, enabled: false } Server->>Caller: Emit "call:participant-audio-toggled" { callId, userId, enabled: false } Note over Caller, Callee: Phase 5: Termination Caller->>Server: Emit "call:end" { callId } Server->>Caller: Emit "call:ended" { callId, endedBy, duration } Server->>Callee: Emit "call:ended" { callId, endedBy, duration } else Option B: Bob Declines Callee->>Server: Emit "call:decline" { callId } Server->>Caller: Emit "call:declined" { callId, calleeId } end

5.2 Flow Details

Phase 1: Call Setup (SDP Exchange)

  1. Alice (caller) emits call:initiate with target conversationId, type: 'VIDEO', and her local WebRTC SDP offer.
  2. Server creates the database call record, joins Alice as a participant, emits call:outgoing back to Alice to acknowledge, and emits call:incoming to Bob (callee) with Alice's offer and profile info.
  3. Bob's client receives call:incoming, plays the ringtone, and emits call:ringing back to the server.
  4. Server relays call:ringing to Alice so her screen displays "Ringing...".

Phase 2: Connection Establishment

  1. Bob (callee) clicks "Accept". His client creates a WebRTC answer and emits call:accept with his SDP answer.
  2. Server updates the call status to ACTIVE, joins Bob as a participant, and relays call:accepted to Alice with Bob's SDP answer.
  3. Alice and Bob establish direct WebRTC connection.

Phase 3: ICE Candidate Exchange

  1. Both clients gather ICE candidates and emit webrtc:ice-candidate with the candidate details and the target's userId.
  2. Server saves these candidates to the database for call auditing and relays them immediately via webrtc:ice-candidate to the target.

Phase 4: Active Controls & Call Termination

  1. If Bob mutes himself, his client emits call:toggle-audio with enabled: false. Alice receives call:participant-audio-toggled to update Bob's mute icon.
  2. When Alice clicks "Hang up", her client emits call:end.
  3. Server updates the call status to ENDED, calculates participant durations, and emits call:ended to all users in the conversation.
